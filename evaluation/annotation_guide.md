# 人工标注指南

回放脚本会生成 `results/annotation_batch.csv`，不要在模板文件上直接改。复制批次文件后再标注。

## 字段

| 字段 | 取值 | 说明 |
|---|---|---|
| `human_relevance_0_2` | 0 / 1 / 2 | 事件是否与所选话题相关：0 无关，1 勉强相关，2 直接相关 |
| `human_time_fit_0_1` | 0 / 1 | 事件日期是否真正落在所选时间窗内；日期未确认记为 0 |
| `human_fact_support_0_2` | 0 / 1 / 2 | 逐条对照引用片段：0 片段不支持，1 部分支持，2 直接支持 |
| `human_independent_confirmation_0_1` | 0 / 1 | 是否存在真正独立的第二来源，而不是转载或同一公告的镜像 |
| `human_change_judgment` | `new` / `updated` / `unchanged` / `no_event` | 与上一轮相比是新事件、实质更新、重复还是本来就不该有事件 |
| `human_note` | 自由文本 | 例如“性能数字缺少 batch size”“官方与社区结论冲突” |

`auto_time_fit` 只是机器比较事件日期与固定参考日期，不能替代 `human_time_fit_0_1`。

## 标注步骤

1. 先看 `scenario` 与 `case_type`，不要先看自动结果。
2. 打开对应固定材料或实时来源原文（回放场景在 `evaluation/fixtures.py`）。
3. 对每条事件独立填写相关性和时间符合度。
4. 抽查所有事实引用：片段必须能在实际读取的正文中找到，并判断语义是否支持陈述。
5. 判断来源是否真正独立。“转载”“综合报道”不算独立确认。
6. 完成变更判断。`__NO_EVENT__` 行用于确认“无事件”是否正确。
7. 由第二个人抽查至少 20% 的行；分歧记录在 `human_note`，不要直接取平均。

## 汇总

人工指标与自动指标要分表报告：

- 人工相关性均值、时间符合率
- 人工引用支持率
- 人工独立确认率
- 人工变更判断准确率
- 人工参考事件覆盖率（只使用事前定义的标准事件，不用系统输出反过来当答案）

样本量小或只有一个标注人时，明确写出限制，不报告显著性。
